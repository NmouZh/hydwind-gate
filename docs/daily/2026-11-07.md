修复 `feat/login-gate` 代码审查遗留问题（分支 `fix/review`），不重新审查，直接按清单改。

### 改了什么

- **429 限流**：`VerifyResult` 新增 `RATE_LIMITED` 与 `retryAfterMs`、`attemptsRemaining`；`HttpWebsiteClient` 把 429 映射为限流，优先读响应体的 `retryAfterMs`，缺失时回退 `Retry-After` 头。`LoginManager` 显示「尝试过多，请 X 秒后再试」，不触发不可达回调（因此也不触发探活与受控重启）。
- **409 game_id_mismatch**：解析可选的 `expectedGameId`，有值时文案点名「此账号对应游戏 ID 为 X」，没有时沿用通用文案。
- **归一化统一**：`LoginManager` 改用 `KaomojiCode.normalize`，ASCII 部分大小写不敏感；`isBlankOrTooLong` 真正接进提交路径（空码/超长码不请求网站），删除无用的 `looksLikeFallback`。
- **成功信息与对话框**：成功文案按 `role=admin` 分流，优先显示中文别名；对话框正文保证包含网站 URL（模板没写 `{url}` 时自动补上）。
- **reload 不丢重启策略**：插件保留同一个 `RestartPolicy` 实例，用 `reconfigure(RestartSettings)` 更新参数，冷却与窗口内计数不再清零。
- **冻结命令**：`/login` 无条件放行，`/hydwind` 仅在有 `admin.permission` 时放行，其余命令取消。
- **文案可配置**：`AdminService` / `AdminCommand` 的中文文案移到 `Messages.admin`（`AdminMessages`），并在 `config.yml` 增加 `messages.admin` 段。
- **结构清理**：抽出 `FreezeController.cancelIfFrozen`、`LoginSessionStore` 的超时判断；新增 `web.Urls.stripTrailingSlashes`，`RestartPolicy` 增加接收 `RestartSettings` 的构造器。
- **对话框按钮**：Paper Dialog 的静态动作支持 `openUrl`，`重新打开网站` 按钮现在真的打开网站，不再走自定义 reopen 事件。
- **文档**：README 统一用「登录码」；spec 模块列表去掉未实现的 `HealthProbe`，注明健康检查是 `WebsiteClient.health()`。
- **测试依赖**：`build.gradle.kts` 补上 `paper-api` 的 `testImplementation`（原注释声称测试运行时会引入同一 API 版本，但依赖缺失），否则引用 `FreezeController` / `DialogFactory` 的测试无法编译。

### 为什么

审查指出的都是行为缺口或可维护性问题：限流被误判为不可达会触发不必要的重启；reload 重置策略会绕过重启冷却；硬编码文案无法配置；冻结期放行过宽。集中修掉避免留到上线后。

### 怎么验证

- 新增/更新 JUnit：`HttpWebsiteClientTest`（429 响应体/Retry-After 头、expectedGameId）、`LoginManagerTest`（限流、限流无 retry、expectedGameId、大小写归一化、超长码、admin 文案）、`RestartPolicyTest`（reconfigure 保留冷却/计数、RestartSettings 构造器）、`FreezeControllerTest`（命令放行规则）、`DialogFactoryTest`（URL 正文）、`UrlsTest`。
- 按工作区规则本地不跑 Gradle；验证走 GitHub Actions：`gh run list -R NmouZh/hydwind-gate --branch fix/review`。结果以 CI 为准。
- 游戏内行为（限流提示、按钮打开浏览器、冻结期命令）仍按 `docs/manual-test.md` 手工复检。

### 遗留

- 限流响应字段名按 `retryAfterMs` / `attemptsRemaining` 假定，需网站端确认；`Retry-After` 只解析秒数，不解析 HTTP-date。
- `attemptsRemaining` 已解析但暂未用于文案（避免过度提示）。
- 未本机运行构建或测试，首次 CI 结果可能暴露编译细节问题。

V2：Velocity + LimboAPI 的 limbo 登录主流程（分支 `feat/V2`，工作树 `/tmp/hydwind-gate-V2`）。

### 改了什么

- 新增 `login` 包：
  - `LoginCommand`：解析 LimboAPI `onChat` 收到的 `/login <码>`，处理无斜杠、命令大小写、颜文字内部空格、空码与 256 字符上限。
  - `LoginFeedback`：把 `VerifyResult` 映射成文案与动作；成功分流 admin 文案并用别名/账号名/游戏 ID 回退；429 向上取整重试秒数且不触发重启；401 视为配置异常；`UNREACHABLE` 触发受控重启。
  - `PromptText`：把 `messages.gate-prompt` 按 `{url}` 拆成三段；模板缺占位符时自动把网址补在末尾。
  - `LimboSpawn`：解析 `limbo.spawn` 的 `x, y, z[, yaw, pitch]`，非法或非有限值回退 `0, 64, 0`。
  - `LimboLoginService`：从已安装的 `limboapi` 插件实例取 `LimboFactory`，用 `createVirtualWorld` + `createLimbo` 建 limbo，注册 `/login` 的 `LimboCommandMeta`（仅为 Tab 补全），提供 `passLogin` / `spawnInLimbo`。
  - `LoginSessionHandler`：`onSpawn` 发标题与可点击 URL（`ClickEvent.openUrl`）、`disableFalling`、按 `prompt-interval` 重复提示、按 `login-timeout` 定时踢出；`onChat` 异步调用网站校验，成功记录会话后 `LimboPlayer#disconnect(server.main)`，失败提示并保持 limbo；断线取消定时任务。
  - `LoginGateListener`：`PreLoginEvent` 强制离线；`LoginLimboRegisterEvent` 宽限内 `passLoginLimbo`，否则进 limbo；`ServerPreConnectEvent` 拒绝无已认证会话的连接；`DisconnectEvent` 保留宽限记录。
- `HydwindGatePlugin`：初始化 limbo、注册监听器、每分钟清理过期宽限；关服时 dispose limbo 并取消维护任务；reload 保留会话，并提示 limbo 世界/出生点变更需重启代理。
- 文档：`README` 状态更新到 V2；`docs/manual-test.md` 重写为 Velocity + LimboAPI 手工清单（limbo、`/login` 成功/失败/429/超时、宽限、后端隔离、fail-closed、配置消费）。
- 测试：新增 `LoginCommandTest`、`LoginFeedbackTest`、`PromptTextTest`、`LimboSpawnTest`，共 65 个测试（含 V1 既有测试）。

- 第一次 CI 失败不是代码问题，是 `PromptTextTest` 期望值写错（模板多写了“登录”两字）；修正断言后通过。

## implementer V3 / Agent · 20:33

### 改了什么

- 新增 `command` 包：`AdminCommandRequest`（纯文本解析）、`AdminStatus`（status 统计与文案）、`AdminCommandExecutor`（执行器）、`HydwindCommand`（Velocity `SimpleCommand`）。
- `HydwindGatePlugin` 注册 `/hydwind`：`CommandManager` 入口 + limbo `onChat` 入口共用同一执行器；权限读 `admin.permission`（默认 `hydwind.admin`），无权限返回提示。
- `status`：limbo 玩家数、待认证/已认证会话数、离线宽限数、网站健康、重启额度与下次允许时间。健康探针放到调度线程，避免阻塞。
- `reload`：调用现有 `reloadConfiguration()`，会话存储与 `RestartPolicy` 历史保留；失败回显 `reload-failed`。
- `approve <玩家>`：先 `LoginSessionStore.forceAuthenticate`，再让 limbo handler 停止提示并转主服（否则 `ServerPreConnectEvent` 会拒绝转服）。
- `kick <玩家>`：清理会话并断开 limbo 或主服中的玩家。
- `LimboLoginService` 增加只读/管理接口：`residents` 注册表、`findLimboPlayer`、`limboPlayers`、`limboPlayerCount`、`approve`、`kick`；`LoginSessionHandler` 在 `onSpawn`/`onDisconnect` 登记与注销。
- `RestartTrigger` 日志从 `java.util.logging` 换成 Velocity 的 SLF4J；插件不再自建 JUL logger。
- `AdminMessages`/`config.yml` 增加 `status-limbo`、`reload-failed` 文案。
- 测试：`AdminCommandRequestTest`、`AdminStatusTest`、`RestartPolicyTest` 新增 reload 保留计数用例、`RestartTriggerTest` 改用 SLF4J + 既有 TempDir/Clock 用例；构建补 `slf4j-api`/`slf4j-simple` 测试依赖。

### 为什么 / 踩过的坑

- limbo 内命令被 LimboAPI 吞掉，`CommandManager` 不参与，所以两个入口必须共用 `AdminCommandExecutor`，否则行为会分叉。
- approve 必须先写会话状态：`ServerPreConnectEvent` 只看 `LoginSessionStore`，只断开 limbo 玩家会被门禁拦下。
- 手动放行时还要停掉 `LoginSessionHandler` 的重复提示与超时任务，否则玩家转服后仍会收到 limbo 提示。
- `reload` 保留策略计数由既有 `RestartPolicy.reconfigure` 保证；新增用例覆盖“上限变小也不清历史”。

### 怎么验证

- 本机按工作区规则不跑构建/测试；推送后看 GitHub Actions。
- 待记录：CI run id、测试数、artifact 结果。

### 遗留

- 未做真实客户端手工验证（limbo 内 `/hydwind`、approve 转服、kick）。
- `status` 的健康探针每次都会发一次 HTTP 请求；若网站很慢，命令返回会延迟，但不会阻塞主线程。

# HydwindGate 手工验证清单

本清单覆盖无法在 JUnit 中验证的游戏内行为。全部手工项在 Paper 26.3 测试服上执行，**不在 CI 中运行**。

## 0. 准备

- [ ] 构建产物：GitHub Actions `CI` 成功，下载 `build/libs/HydwindGate-0.1.0.jar`。
- [ ] 网站 `feat/login-gate` 已部署，`/api/health` 返回 `{"ok":true,...}`，`PLUGIN_TOKEN` 已配置。
- [ ] 测试服安装插件，`config.yml` 填入正确的 `website.base-url`，并通过环境变量 `HYDWIND_PLUGIN_TOKEN` 提供令牌。
- [ ] 创建 `/run/hydwind` 目录并确保运行 Minecraft 的用户可写（或把 `restart.request-file` 指向可写路径）。
- [ ] 至少准备两个网站账号 A、B，账号名分别与两个 Minecraft 游戏 ID 相同。
- [ ] 启动方式二选一：
  - `gradle runServer`（`xyz.jpenilla.run-paper` 3.1.0，Minecraft 26.3）；
  - 或手动下载 `paper-26.3-244.jar`，放入空目录后执行 `java -jar paper-26.3-244.jar --nogui`，再把插件 jar 放入 `plugins/`。

## 1. 冻结与对话框

- [ ] 以未登录玩家进服：玩家被传送到 `spawn` 配置的位置，冒险模式、隐身、无敌。
- [ ] 玩家无法移动、挖掘、放置、攻击、受伤、聊天、执行其他命令、与方块/实体交互。
- [ ] 进服即弹出「氢风门禁」对话框，正文包含可点击的网站 `/gate` 链接。
- [ ] 按 Esc 无法关闭对话框。
- [ ] 对话框输入框可粘贴、可输入；「提交验证」与「重新打开网站」按钮可见。
- [ ] 网站 `/gate` 页面显示颜文字码和 `HWG-XXXX` 备用码，URL 指向配置的 `website.base-url`。

## 2. 粘贴与 `/login`

- [ ] 从网站复制颜文字码，在对话框中粘贴并提交：提示验证中，随后解冻并收到欢迎语。
- [ ] 若对话框粘贴不可用，执行 `/login <颜文字码>`：同样的成功路径。
- [ ] 执行 `/login HWG-XXXX`（ASCII 备用码，大小写混写）：成功。
- [ ] 无参数 `/login`：重新弹出对话框。
- [ ] 登录成功后，玩家可移动、交互、聊天；`/login` 提示「已经完成认证」。
- [ ] 未登录玩家执行 `/login <随机码>`：收到「登录码不存在」，仍保持冻结。

## 3. 错误码

逐项准备对应条件，确认玩家仍被冻结且收到准确文案：

- [ ] `invalid_code`：随机/错误登录码 → 「登录码不存在」。
- [ ] `expired`：生成码后等待超过 5 分钟再提交 → 「登录码已过期」。
- [ ] `used`：同一码成功使用一次后，用账号 B 或重连再提交 → 「登录码已被使用」。
- [ ] `game_id_mismatch`：用账号 B 生成码，但在帐号 A 的游戏 ID 下提交 → 「网站账号名与你的游戏 ID 不一致」。
- [ ] `401`：临时填错插件令牌并 `/hydwind reload` → 「认证服务配置异常，请联系管理员」。
- [ ] 恢复正确令牌后 `/hydwind reload`，登录恢复正常。

## 4. 超时踢出

- [ ] 未登录玩家挂机超过 `login.timeout-seconds`（默认 300 秒）。
- [ ] 玩家被踢出，踢出原因包含「登录超时」。
- [ ] 会话被清理：`/hydwind status` 的待认证数量回到踢出前水平。
- [ ] 超时后迟到的校验结果不会解冻玩家（可让网站故意延迟响应验证）。

## 5. 重连宽限

- [ ] 已认证玩家断线，5 分钟内以相同 UUID + 相同 IP 重连：直接放行，不冻结、不弹对话框。
- [ ] 同样条件但更换 IP 后重连：重新进入冻结流程。
- [ ] 超过 5 分钟后重连：重新进入冻结流程。
- [ ] 服务器重启后重连：会话清空，重新进入冻结流程。

## 6. 网站不可达（fail-closed）

- [ ] 停止网站进程或断开网络，玩家执行 `/login <有效码>`。
- [ ] 玩家收到「认证服务暂时不可用，请稍后重试」，仍保持冻结；**绝不解冻**。
- [ ] `plugins/HydwindGate/logs` 或控制台出现健康检查失败与重启触发日志。
- [ ] 恢复网站后再次提交有效码：登录成功。

## 7. 重启请求文件与冷却

- [ ] 网站不可达时，第一次登录尝试写出生效的 `restart.request-file`，内容包含 `reason=website-unreachable` 和 UTC 时间戳。
- [ ] 删除请求文件后 10 分钟内再次触发：不重新写入，控制台出现「被策略拒绝」告警。
- [ ] 等待冷却结束后可再次写入。
- [ ] 一小时内完成 2 次成功后，第 3 次被拒绝，只记录告警，服务器不重启。
- [ ] 把 `restart.request-file` 指向不可写路径（如 `/proc/nope/request`）并触发：只出现写入失败告警，登录流程仍返回「服务不可用」，插件无异常堆栈。
- [ ] 若已配置 systemd `hydwind-restart.path`：文件出现后网站被重启、文件被清除。

## 8. `/hydwind` 管理命令

以拥有 `hydwind.admin` 的账号（或控制台）执行：

- [ ] 无权限玩家执行 `/hydwind status`：提示缺少权限。
- [ ] `/hydwind status`：显示待认证数量、已认证数量（含离线宽限）、网站健康状态与 uptime、重启剩余额度；网站不可达时显示「网站: 不可达」。
- [ ] `/hydwind approve <玩家>`：目标玩家立即置为已认证并解冻，可正常游戏。
- [ ] 对已认证玩家执行 approve：提示「已经通过认证」。
- [ ] 对不存在的玩家执行 approve/kick：提示找不到会话。
- [ ] `/hydwind kick <玩家>`：玩家被踢出，原因提示管理员踢出；会话被清理，`status` 计数下降。
- [ ] `/hydwind reload`：修改 `website.health-path` 或 `messages.gate-title` 后执行，新配置生效；进行中的未登录会话仍可继续提交登录码，已冻结玩家不会解冻。
- [ ] `/hydwind`（无参数）：显示用法。
- [ ] 未知子命令：显示用法，不抛异常。

## 9. 收尾

- [ ] 控制台无插件异常堆栈（`WARN` 级的策略拒绝与写入失败属于预期）。
- [ ] 执行 `/hydwind status` 核对最终会话数量为 0（除在线已认证玩家）。
